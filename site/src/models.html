Models and setup

Qvault works out of the box with pattern and heuristic detection. Two optional features need model files on your computer: AI detection (Layer 3) and OCR for scanned documents. This page explains where the files come from and how to install them.

What needs a model

FeatureModelHow to get it
Layers 1–2 (patterns, heuristics)NoneBuilt in
Layer 3 (local AI)OpenAI Privacy Filter (default); Qwen3 language models for an optional thorough passDownload in the app, or import from a file
Entity grouping (optional similarity)Nomic Embed Text v2 MoEDownload in the app, or import from a file. Grouping works without it.
OCR (scanned PDFs, PNG, JPG, TIFF)CRAFT detector + Latin recognizerDownload manually, then import

All models are managed in Settings → AI Detection (the Model Manager). Models are stored in Qvault’s app data folder, are checked against a pinned SHA-256 before first use in each session, and can be deleted at any time. AI and OCR are available in the desktop app only.

AI detection models (Layer 3)

In the Model Manager, click Download next to a model. Qvault shows the size and the source host before anything is transferred. The download comes straight from Hugging Face over HTTPS (never peer-to-peer), shows real progress, can be cancelled, and is verified against the size and SHA-256 below before it is moved into place.

Privacy Filter (default detector)

OpenAI Privacy Filter is the recommended detector. It labels each page in one pass, in about 0.2 seconds on a CPU, and needs about 2 GB of memory. It is four files (about 1.65 GB in total) from the pinned revision of openai/privacy-filter, Apache-2.0. The Model Manager downloads all four; to import, choose Import folder… and pick a folder that contains them (the Hugging Face layout with an onnx/ subfolder also works), or import the files one at a time. Qvault keeps a partial set until the last file arrives.

Privacy Filter does not look for company names, amounts or case numbers; Layers 1–2 still cover those, and the optional thorough pass below adds a language model.

Then turn on Use AI detection (Layer 3) when scanning. AI findings are labelled with the detector that found them and added with a confidence that depends on the category (for example 80% for names, down to 50% for addresses and case numbers) and always wait for your review. If Privacy Filter cannot run, the scan uses the language model if one is installed. If the AI engine is unavailable or a chunk fails, the scan still completes with Layers 1–2 and the viewer tells you what was skipped.

Entity grouping model (optional)

Qvault groups spellings of the same name, company or number with rules that need no model. An optional embedding model adds extra proposals based on meaning; it never merges anything by itself. On our small test set it did not improve the result, so you can skip it.

OCR models: download and import

The OCR models are not downloaded by the app. Download the two files below yourself, check them, and import them. You only need to do this once per computer.

FilePurposeSizeLicence
craft_mlt_25k.gguf CRAFT text detector (finds text on the page) 83,133,856 bytes (≈ 83 MB) MIT (weights, NAVER Clova AI); GGUF conversion Apache-2.0
latin_g2.gguf EasyOCR Latin recognizer (reads the text) 15,396,512 bytes (≈ 15 MB) Apache-2.0

SHA-256 (craft_mlt_25k.gguf): 74501993caf4581ce09b280f49a1b3d249c0f5a78496e047718b398457a875aa
SHA-256 (latin_g2.gguf): dd1c7a436e9175904e63683e939635892f45c8c6377d5e14e87cf8b175e10768

  1. Download both files into one folder, for example Downloads/qvault-ocr. Use the links in the table above. Keep the file names unchanged.
  2. Verify the checksums (see below). Each printed hash must match the table exactly.
  3. Open Qvault → Settings → AI Detection and find OCR models.
  4. Click Import from file… and choose craft_mlt_25k.gguf. Repeat for latin_g2.gguf. Qvault recognises each file by its SHA-256 and copies it into its model folder.
  5. Optional: click Test AI engine to run OCR on a built-in sample image. You can then delete the downloaded copies.

Verifying checksums

Qvault checks the hash itself on import, so a damaged or altered file is rejected either way. Checking it yourself first is good practice, and it is how you confirm that a file copied onto removable media is intact.

macOS and Linux

cd ~/Downloads/qvault-ocr
shasum -a 256 craft_mlt_25k.gguf latin_g2.gguf
# Linux also has: sha256sum craft_mlt_25k.gguf latin_g2.gguf

Windows (Command Prompt)

cd %USERPROFILE%\Downloads\qvault-ocr
certutil -hashfile craft_mlt_25k.gguf SHA256
certutil -hashfile latin_g2.gguf SHA256

In PowerShell you can use Get-FileHash .\craft_mlt_25k.gguf -Algorithm SHA256. Windows prints the hash in upper case; compare it ignoring case.

Expected output:

74501993caf4581ce09b280f49a1b3d249c0f5a78496e047718b398457a875aa  craft_mlt_25k.gguf
dd1c7a436e9175904e63683e939635892f45c8c6377d5e14e87cf8b175e10768  latin_g2.gguf

Air-gapped machines

Many firms keep document review machines off the network. Qvault supports this fully:

  1. On a connected computer, download the Qvault installer from GitHub Releases, the two OCR files above and, if you want Layer 3, the four Privacy Filter files and optionally a Qwen model file from the links below.
  2. Verify every checksum on the connected computer.
  3. Copy the files to removable media and onto the air-gapped machine. Verify the checksums again there.
  4. Install Qvault and import each model with Import from file…. No network connection is needed at any point.

Privacy Filter files at the pinned revision: model_quantized.onnx · model_quantized.onnx_data · tokenizer.json · viterbi_calibration.json

Qwen files at the pinned revisions: Qwen3-1.7B-Q8_0.gguf · Qwen3-0.6B-Q8_0.gguf · Qwen3-4B-Q4_K_M.gguf · Qwen3-8B-Q4_K_M.gguf · qwen2.5-0.5b-instruct-q4_k_m.gguf · qwen2.5-1.5b-instruct-q4_k_m.gguf

Troubleshooting

  • “Unrecognised model file”. The file’s hash does not match any model Qvault knows. It is usually an incomplete download: download it again and re-check the hash. Do not accept an unknown file for OCR.
  • “AI engine is not included in this build”. You are running a build without the bundled QVAC helper (for example a plain cargo build). Layers 1–2 still work; use an official release for AI and OCR.
  • “Likely too large for this computer”. Qvault checks whether a model fits your memory before loading it. Choose a smaller model, such as Qwen3 0.6B, or use Privacy Filter without the thorough pass. The Model Manager shows each model’s memory need next to your computer’s memory before you download.
  • Windows. The QVAC runtime needs a recent Vulkan driver even for CPU inference. On virtual machines or very old graphics hardware, AI and OCR may be unavailable; Layers 1–2 are unaffected.
